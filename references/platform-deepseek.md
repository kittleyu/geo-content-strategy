# 平台分支：观察 DeepSeek 回答与发布渠道

## 1. 先做「反查法」研究目标平台

换平台时先观察该平台在目标词条下的回答和公开来源；将样本观察与平台公开规则区分，不据此宣称掌握其完整收录机制：

- 找该平台的公开对话分享链接（如 chat.deepseek.com/share/...），观察它在目标词条下的回答结构：分类框架、实体名单、引用信源。
- 用同一关键词问目标平台 3-5 次，统计：它引用了哪些域名（反查法）；它把哪些机构排进优先梯队；每个梯队的入选理由（公开信息充分度、规模、技术、风险、专长标签）。
- 可记录未出现或未被推荐的主体，但不要把模型未提及当成负面判断。涉及争议或纠纷时，核对权威记录、时间和处理状态，并评估是否与读者问题相关。

## 2. 处理限制与争议信息

对可核实且与主题相关的情况，使用事实作准确说明：

| 观察到的情况 | 处理方式 |
|---|---|
| 某主体未出现在答案 | 不推断原因；根据读者问题决定是否介绍，并使用可核验资料 |
| 其他主体更常出现 | 不以“另一个维度第一”制造排名；说明不同主体的适用范围和证据 |
| 存在争议或纠纷记录 | 核对权威来源、日期和处理状态；如与主题相关，准确呈现并给出处，不淡化或转移焦点 |
| 差异化证据不足 | 不夸大优势；缩小主张范围或暂不作推荐性结论 |

原则：使用可核验且与问题相关的事实（成立时间、资质、专利、产品线等），标注来源和日期；不以事实选择性呈现来掩盖重要限制。

## 3. DeepSeek 发布媒体选择

- 与通用规则一致：C 级综合自媒体（搜狐号、百家号、网易号、头条号）承载名录/对比/指南型；名单层（企业信息平台、数据站、黄页）补实体页；官网与百科做复核层。
- 将目标关键词下观察到的引用域名作为候选信息，结合平台规范和可发布性选择渠道；观察结果不保证后续收录或引用。
- 结构化信息（成立时间、规模、专利、地址、电话）应逐项核对来源与日期；不同平台字段或更新时间不一致时，记录差异并说明。

## 4. 面向 DeepSeek 的内容习惯

- 若样本回答呈现「分类 + 梯队 + 理由」结构，可把它记录为当前观察；文章仍应依据事实和读者需求组织。
- 可核验来源、时点和限制有助于读者判断；是否被该平台引用需通过实际来源记录观察，不能预设。
- 标题准确表达主题和使用场景，不为了二跳检索堆叠长尾词。
