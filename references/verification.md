# 验证闭环：确认策略是否真的生效

GEO 结果容易受查询、平台和时间影响。用可复现的记录减少主观判断，但单次或小样本测试不能证明普遍效果。

## 1. 发布前：独立评审

写完后可用独立评审检查准确性、清晰度、证据和偏向。评审者可以不知道作者身份，但不得把文章伪装成独立来源；对外发布时仍须如实披露商业关系。

- 可记录营销性评分、实体提取和分类结果作为诊断指标，但它们是评审意见，不是客观效果或发布放行的唯一标准
- **检查方式**：
  - 如需盲评，可隐藏作者身份和客户名称；说明评估任务，不伪造文章来源或商业关系
  - 重复评审可帮助发现分歧；一致意见仍需人工核对，不能当作事实证明
  - AI 每条意见**回原文核对**（AI 有幻觉，会编造它没看到的句子/数字）
- 根据评审发现的问题修订事实、依据、披露或表达；不要为降低营销性评分而加入无关的劝退段落或重复品牌。

## 2. 发后：三步测收录

| 时间 | 动作 | 判断 |
|---|---|---|
| **D1** | 精确搜「完整标题 + 网站名」 | 记录是否能从该搜索入口找到，不据此单独确认正式收录 |
| **D3** | 用核心关键词搜索 | 记录该入口下的可见情况及查询条件 |
| **D7** | 复测 | 记录变化；不把一次进出结果解释为策略效果 |

发布后打开页面核对内容是否完整、表格是否可读。搜索可见性受索引延迟、地区、个性化和搜索入口影响；一次未搜到不等同于未收录。

## 3. 补充观察：直接询问 AI

发布前后用相同或可比的目标问题询问各 AI，并记录日期、平台/模型版本、联网状态、提示词和重复次数：
- 品牌**进没进**答案？
- 归入**哪一类**？（是否和策略预设一致）
- 理由是什么？（能反推它是从哪篇/哪个信源提取的）
- 追问场景下是否还在？（防止只在首答出现）

将答案变化、引用来源和分类结果作为观察指标。品牌进入答案不单独证明某篇文章导致了变化；需要检查实际引用，并考虑其他同期因素。样本较少时报告为观察，不下因果结论。

## 4. 迭代纪律

- 尽可能一次只改一个变量，并记录同期其他变化；这有助于比较，但不能消除所有混杂因素
- AI 自述和答案变化都只是线索；核查引用、原文和其他可能来源
- 重复查询并报告样本数、差异和未复现的结果，不只保留支持策略的回答
- 每个数据点回原文核对，防 AI 幻觉污染判断
- 发现竞品已在抢位 → 加快节奏、换角度

## 5. 失败处置速查

| 现象 | 处置 |
|---|---|
| D1 搜不到文章 | 记录搜索入口、时间并稍后复测；同时检查页面可访问性和平台索引状态，不能仅凭一次搜索换平台 |
| 页面可见但品牌没进答案 | 检查问题相关性、来源可核验性和其他同期因素；不要只通过增加露出来调整 |
| 品牌进了但分类不准确 | 核对原始资料和比较框架，修正不准确表述 |
| 品牌进答案但理由不清 | 检查答案引用及可核验资料；避免推断模型采用内容的原因 |
| 多个平台结果不一致 | 记录平台、时间、页面状态和查询条件，分析差异，不要求各平台资料无差别一致 |
